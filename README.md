# VNO Era — Vilniaus oro uosto atvykimai (PWA)

Мобильное приложение для тех, кто встречает рейс в VNO. Показывает ближайший прилёт с обратным
отсчётом, когда пассажиры выйдут в зал прилёта, ленту прилётов, радар-карту и умеет следить за рейсом.

Приложение сделано в первую очередь для iPhone и Android. Оно устанавливается на домашний экран как
PWA. Десктоп поддерживается как дополнительный режим.

## Как это устроено

```
GitHub Pages ── раздаёт приложение и data/arrivals.json (видят все по ссылке)
      ▲
GitHub Actions «Update arrivals» ── запускает ТОЛЬКО владелец репозитория
      │  ключи — в Secrets, не в коде и не в браузере
      └─ AirLabs (расписание) + OpenSky (координаты) → data/arrivals.json → коммит → деплой
```

- **Посетители** только читают готовый `data/arrivals.json`. Они не могут потратить ни одного
  запроса к API.
- **Автообновление:** workflow запускается каждые 15 минут, но запрос к API делает, только когда
  это позволяет бюджет. Скрипт делит остаток месячного лимита AirLabs на оставшиеся дни месяца и
  равномерно распределяет обновления с 06:30 до 23:45 по Вильнюсу. Ночью запросы не тратятся.
  При лимите 1000 запросов это около 15 обновлений в день, примерно раз в час. Если в месяце
  остался запас, обновления идут чаще. 20 запросов остаются в резерве для ручных обновлений
  (`MANUAL_RESERVE`).
- **Владелец** может обновить данные вне расписания одним из двух способов:
  - кнопкой «Atnaujinti iš AirLabs» в приложении (Nustatymai → Savininko režimas);
  - в GitHub: Actions → Update arrivals → Run workflow.
- **Лимиты** задаются в `.github/workflows/update.yml`:
  - не больше **30 обновлений в день** по времени Вильнюса (`DAILY_LIMIT`) — это страховочный
    предел, реальную частоту задаёт месячный бюджет;
  - не больше **1000 запросов AirLabs в месяц** (`MONTHLY_LIMIT`, бесплатный тариф).

  Одно обновление тратит 2 запроса AirLabs:
  - расписание — одна страница из 50 записей (`MAX_PAGES`), это примерно 12 часов прилётов;
  - список самолётов, летящих в VNO, с их бортовыми ICAO-адресами.

  Счётчики видны в настройках.

Секреты репозитория (Settings → Secrets and variables → Actions):

| Секрет | Обязателен | Зачем |
|---|---|---|
| `AIRLABS_KEY` | да | Ключ AirLabs |
| `OPENSKY_CLIENT_ID`, `OPENSKY_CLIENT_SECRET` | нет | API-клиент OpenSky. Без него запрос идёт анонимно, с ним лимит больше и надёжнее (4000 кредитов в день) |

### Режим владельца в приложении

1. Создайте на GitHub **fine-grained token**: Settings → Developer settings → Fine-grained tokens.
   - Repository access: только этот репозиторий.
   - Permissions → **Actions: Read and write**.
2. В приложении откройте Nustatymai → Savininko režimas и вставьте токен. Он хранится только в
   `localStorage` этого устройства и уходит только на `api.github.com`.
3. Нажмите «Atnaujinti iš AirLabs». Примерно через 1–2 минуты приложение само подхватит
   новые данные.

Этот токен может только запускать workflow этого репозитория. Если телефон потерян, отзовите
токен на GitHub.

## Локальный запуск

```bash
python3 -m http.server 5291
```

Чтобы обновить данные локально, положите ключ в `.env` (`AIRLABS_KEY=...`). Этот файл в
`.gitignore`. Затем выполните `node tools/fetch-arrivals.mjs`: скрипт сделает один запрос с теми
же лимитами.

## Структура

| Файл | Назначение |
|---|---|
| `.github/workflows/update.yml` | Деплой на Pages; ручной запуск — AirLabs + OpenSky |
| `tools/fetch-arrivals.mjs` | Одно обновление с проверкой лимитов → `data/arrivals.json` |
| `tools/airlabs.mjs` | Запрос и нормализация расписания AirLabs |
| `tools/opensky.mjs` | Координаты из OpenSky и сопоставление с рейсами |
| `data/arrivals.json` | Последние данные и счётчики использования |
| `index.html` | Оболочка, SVG-иконки, мета-теги iOS/Android, splash-экраны |
| `styles.css` | Mobile-first стили, safe areas, светлая и тёмная темы, брейкпоинты |
| `i18n.js` | Все строки интерфейса: литовский (по умолчанию), русский, английский |
| `app.js` | Экраны, bottom sheets, уведомления, установка, офлайн, режим владельца |
| `data.js` | Справочник аэропортов, демо-провайдер, расчёт статусов и окна выхода |
| `map.js` | Радар-карта на SVG |
| `sw.js` | Service worker: кэш оболочки, офлайн, клики по уведомлениям, `push` |
| `manifest.webmanifest`, `icons/`, `splash/` | PWA: манифест, иконки, splash-экраны |

## Языки

Основной язык — **литовский**. Русский и английский переключаются в Nustatymai → Kalba, выбор
сохраняется на устройстве. Переведено всё:

- интерфейс и статусы рейсов;
- уведомления и текст «Поделиться»;
- офлайн-страница;
- подписи на карте;
- формат дат.

Названия аэропортов и городов остаются латиницей, как на табло аэропорта.

## Данные: AirLabs + OpenSky

**Расписание.** Workflow запрашивает AirLabs `GET /api/v9/schedules?arr_iata=VNO` (до 2 страниц по
50 записей). Время берётся из полей `*_ts`, то есть сразу в UTC. Codeshare-записи (с полем
`cs_flight_iata`) отбрасываются, остаётся только рейс оперирующей авиакомпании.

**Координаты.** Номер рейса и позывной самолёта часто не совпадают: у Wizz, Ryanair и airBaltic
позывные буквенно-цифровые (`WZZ6655`, `RYR4QK`), к тому же рейс может выполнять дочерняя
авиакомпания. Поэтому самолёт ищется точно, без угадывания:

1. AirLabs `/flights?arr_iata=VNO` отдаёт для каждого рейса в воздухе его бортовой ICAO-адрес
   (`hex`).
2. По этому адресу берётся свежая позиция из The OpenSky Network (`/states/all`).
3. Если OpenSky самолёт не видит (например, у земли возле Вильнюса нет приёмников), используется
   позиция от AirLabs.

Между обновлениями приложение ведёт самолёт от реальной точки по кратчайшему маршруту так, чтобы
он прибыл в VNO к расчётному времени. Рейсы без найденных координат показываются по расписанию.
Легенда на карте показывает, на какое время взяты координаты OpenSky.

К OpenSky нельзя обращаться прямо из браузера: сервер не разрешает запросы с других сайтов
(CORS). Для по-настоящему живой карты у каждого посетителя нужен прокси, например бесплатный
Cloudflare Worker.

**Статусы.** Посадка определяется по фактическому времени. Если расчётное время прошло больше
5 минут назад, а подтверждения нет, рейс показывается как «Tikriausiai nusileido» (вероятно,
приземлился). Уведомление о посадке приходит только по фактическим данным.

### Демо-режим

В Nustatymai → Šaltinis → Demo включается симулированное расписание без сети и без ключа.

## Уведомления: что реально работает

| Платформа | Что работает |
|---|---|
| Android, Chrome (вкладка или установленная PWA) | Системные уведомления, пока приложение открыто или его процесс ещё жив в фоне |
| iPhone/iPad, Safari, **обычная вкладка** | Системных уведомлений нет: Apple их там не даёт. Работают только in-app алерты, приложение показывает инструкцию по установке |
| iPhone/iPad, **установленная PWA** (iOS 16.4+) | Notification API доступен после разрешения; уведомления появляются и на экране блокировки |
| Десктоп (Chrome, Edge, Safari, Firefox) | Системные уведомления, пока вкладка открыта |

Важно: проверка алертов (за 60, 30 и 15 минут, «приземлился», задержка или отмена, «изменилось
время выхода») выполняется **в самом приложении**, раз в 30 секунд. Если приложение полностью
закрыто, а на iOS — даже просто свёрнуто, JavaScript не выполняется, и такие алерты не придут.
Поэтому в экране «Waiting time» есть переключатель «Keep screen on» (Screen Wake Lock API).

**Чтобы уведомления приходили при закрытом приложении**, нужен Web Push:

1. Сервер с VAPID-ключами (например, `web-push` на Node).
2. На клиенте: `registration.pushManager.subscribe({ userVisibleOnly: true, applicationServerKey })`.
   Подписку и список отслеживаемых рейсов нужно отправить на сервер.
3. Сервер следит за рейсами и отправляет push с JSON `{ title, body, flightId }`.

Обработчик `push` в `sw.js` уже есть и покажет такое уведомление. Серверная часть **не реализована**,
и приложение не делает вид, что она есть. На iOS Web Push работает только в установленной PWA.

Чего PWA сделать не может в принципе: виджеты, Live Activities и Dynamic Island на iOS, постоянное
уведомление на Android. Это доступно только нативным приложениям.

Что есть дополнительно: значок на иконке приложения с числом отслеживаемых рейсов (Badging API,
установленная PWA) и вибрация при действиях на Android.

## Установка

- **Android, Chrome, десктопный Chrome и Edge** — кнопка «Install» в шапке вызывает системный
  диалог установки (`beforeinstallprompt`).
- **iOS** — кнопка «Install» открывает инструкцию: Share → Add to Home Screen → Add. Её можно
  скрыть на 3 дня кнопкой «Not now».
- Если приложение уже установлено (`display-mode: standalone`), кнопка не показывается.

## Офлайн и сеть

- Оболочка приложения кэшируется при первом визите и затем открывается без сети: сначала из кэша,
  потом обновляется в фоне (stale-while-revalidate). Навигация идёт network-first с таймаутом 3 с.
- Последний снимок данных хранится в `localStorage`, поэтому холодный старт показывает данные
  мгновенно.
- Без сети появляется плашка «**Offline · Last updated 2 min ago**», а индикатор в шапке меняется
  с «Live» на «Offline».
- При событии `online`, при смене Wi-Fi ↔ мобильная сеть и при возврате в приложение данные
  обновляются автоматически. При ошибках повторы идут с экспоненциальной задержкой.
- **При каждом релизе меняйте `VERSION` в `sw.js`.** Тогда пользователи получат тост «A new version
  is ready · Reload».

## Производительность и батарея

- Никаких фреймворков и тайлов карт. JS весит около 24 КБ в gzip, CSS — около 8 КБ.
- Каждую секунду обновляются только текстовые узлы обратного отсчёта, а не весь интерфейс. Полная
  перерисовка активного экрана происходит раз в 30 секунд.
- Когда вкладка скрыта, таймеры останавливаются. Опрос данных в фоне идёт, только если есть
  отслеживаемые рейсы, и не чаще раза в 2 минуты.
- 3D-наклон радара и анимации сделаны только через CSS transform. Режим **Auto** отключает их на
  слабых устройствах (`deviceMemory`, число ядер, Save-Data, замер FPS при старте) и при
  `prefers-reduced-motion`. Вручную режим меняется в Settings → Effects.

## Мобильный UX

- Нижняя навигация (Home, Arrivals, Map, Watchlist, Settings) учитывает safe area и Home Indicator.
  На ширине от 1024 px она превращается в боковую панель.
- Основные действия собраны в нижней половине экрана: быстрые действия, bottom sheet с кнопками
  внизу, закрытие свайпом вниз, pull-to-refresh, системная кнопка «Назад» на Android закрывает
  sheet.
- Все тач-цели не меньше 44–52 px. Время в 24-часовом формате по Вильнюсу, цифры моноширинные.
- Тема берётся из системы, переопределяется в настройках. Светлая тема — с повышенным контрастом
  для яркого солнца.
- Брейкпоинты: до 359 px (маленькие телефоны), 360–767 px (телефоны), от 768 px (планшет,
  две колонки), от 1024 px (десктоп), отдельно — ландшафт на телефоне.

## Что проверено

Проверено в эмуляции Chromium: 320×640, 375×812, 390×844 (тёмная и светлая темы), 768×1024,
844×390 (ландшафт) и 1280×800. Также проверены:

- регистрация service worker и запуск без сервера из кэша;
- плашка офлайна и автообновление при возвращении сети;
- реальные ответы AirLabs и OpenSky: фильтр codeshare, статусы, сопоставление координат;
- все экраны на литовском, русском и английском;
- что ключ API не попадает ни в один файл репозитория.

На **физических** iPhone и Android приложение не запускалось. Перед публикацией стоит проверить на
реальных устройствах safe area, Dynamic Island, установку и уведомления в установленной PWA на iOS.
